
   VSBVXD - VSBHDA for Windows 3.1 enhanced mode


   1. About

    VSBVXD.386 is the VSBHDA Sound Blaster emulation and sound hardware
   support as a virtual device driver for Windows 3.1/3.11 in enhanced mode.
   VSBHDA itself is a DPMI client of HDPMI; once Windows enhanced mode starts,
   WIN386 takes over the machine and VSBHDA stops working. VSBVXD runs the
   same emulation and sound hardware code in ring 0 of WIN386:

   - DOS programs in DOS boxes get an emulated Sound Blaster (SB, SB Pro,
     SB16) with OPL3, like VSBHDA under plain DOS.
   - Windows programs get the multimedia driver VSBHDA.DRV:
     - wave output: the wave buffers are passed to VSBVXD, which mixes them
       into its output (any PCM format, 8/16 bit, mono/stereo, up to 48 kHz;
       VSBVXD converts the sample rate).
     - MIDI output: a General MIDI synthesizer on VSBVXD's OPL3 emulation
       (18 voices, Freedoom's GENMIDI instrument bank, percussion on channel
       10). The OPL3 is shared with DOS programs, like a real one.
     - aux: the master volume of the sound card.
     Media Player, Sound Recorder, system sounds, MIDI files etc. play
     through the sound hardware, at the same time as DOS programs.

    All sound hardware supported by VSBHDA should work (Intel HDA, ICH/AC97,
   SB Live/Audigy, X-Fi, ES1370/1371, VIA, CS4281); tested so far with the
   QEMU emulations of Intel HDA and ICH AC97.


   2. Installation

    With Control Panel, Drivers, Add, "Unlisted or Updated Driver" and the
   directory with OEMSETUP.INF, VSBHDA.DRV and VSBVXD.386 (drv/OEMSETUP.INF).
   Or by hand:

   - copy VSBVXD.386 and VSBHDA.DRV to the Windows SYSTEM directory.
   - SYSTEM.INI, section [386Enh]:   device=vsbvxd.386
   - SYSTEM.INI, section [drivers]:  wave=vsbhda.drv
                                     midi=vsbhda.drv
                                     aux=vsbhda.drv
   - optional settings in a new section [VSBVXD] (see below).

    MIDI Mapper: on installation (DRV_INSTALL, called by Control Panel)
   VSBHDA.DRV changes the General MIDI setup "Ad Lib general" of MIDIMAP.CFG
   to play all 16 channels on its FM device and makes it the active setup;
   the original file is kept as MIDIMAP.BAK. When installed by hand, select
   or create a setup with Control Panel, MIDI Mapper that sends the channels
   to "VSBHDA OPL3 FM".
   - don't run VSBHDA/SBEMU or another Windows driver for the same sound
     card (they would compete for the hardware), and don't load VSBD.386
     (Microsoft's Sound Blaster VxD) - it traps the same ports.

    VSBVXD needs no DOS components (no HDPMI, no Jemm/QPIEMU, no BLASTER
   variable for itself; DOS programs may need BLASTER set as usual).


   3. Settings ([VSBVXD] in SYSTEM.INI)

     Base=220      SB port (hex)
     IRQ=5         SB interrupt
     DMA=1         SB 8-bit DMA channel
     HDMA=5        SB16 16-bit DMA channel
     Type=6        emulated card: 1/3 = SB 2.0, 4 = SB Pro, 6 = SB16
     OPL3=1        OPL3 emulation at port 388h
     Volume=9      hardware volume 0-9
     Freq=44100    output sample rate
     Device=0      start index of the device scan (HDA)
     Pin=0         output pin (HDA)
     Buffers=0     hardware buffers (0 = default)
     PeriodSize=0  period size (0 = default)
     Compat=0      compatibility flags (VSBHDA's /CF)
     TestTone=0    > 0: play a 440 Hz test tone for that many ms at startup
                   (checks the sound hardware without the emulation)
     LogPort=0     debug log port: a COM port (e.g. 3F8), E9 (Bochs/QEMU debug port)
                   or 0 = off


   4. Building (Linux)

     make -C vxd ASM=jwasm LINK=jwlink    -> build/vxd/VSBVXD.386
     make -C drv ASM=jwasm                -> build/drv/VSBHDA.DRV

    Tools: Open Watcom 2.0 (WATCOM=/opt/watcom by default), JWasm and a
   JWlink whose "format windows vxd" output is fixed for the Windows 3.x
   loader (https://github.com/Baron-von-Riedesel/jwlink/pull/17): no fixup records for self-relative fixups within an object, no
   16-bit fixups in 32-bit objects, and pages for the uninitialized data
   (WIN386 allocates only the pages that are in the file). vxd/lefix.py marks
   the C data object executable - WIN386 3.1 silently skips a VxD with a
   non-executable object.


   5. Tests

    test/win311.sh boots Windows for Workgroups 3.11 in QEMU with VSBVXD
   (WIN311IMG=hard disk image with Windows installed); test/dos/SBPLAY.ASM
   plays a tone with the SB DMA in a DOS box, test/win/PLAYWAV.C plays WAV
   files with sndPlaySound, test/win/MIDITEST.C plays notes on the MIDI
   device and MIDI files with MCI (MIDI Mapper). The sound output of QEMU is
   recorded as a WAV file.


   6. Implementation notes

   - The emulation (src/VSB.C, SNDISR.C, VOPL3.CPP, ...) and the sound
     hardware drivers (src/hw) are used unchanged except SNDISR.C (a few
     #ifdef VSBVXD). The DPMI parts are replaced by vxd/: port traps with
     Install_IO_Handler (all VMs), the SB DMA channels virtualized with VDMAD,
     the SB interrupt with VPICD (requested in the VM that used the SB last),
     the sound hardware interrupt with VPICD, PCI via configuration
     mechanism #1.
   - Every entry from the VMM clears the direction flag: a hardware
     interrupt may arrive while DOS or Windows code runs with DF=1.
   - Memory for the sound hardware is a block of fixed pages that's checked
     to be physically contiguous; _PageAllocate with PageUseAlign returned
     pages that Windows gave to protected-mode programs as well.
   - VSBHDA.DRV calls VSBVXD's protected mode API (device id 7A56h, not
     assigned by Microsoft) and collects the finished wave buffers with a
     multimedia timer. The MIDI synthesizer writes the OPL3 registers to the
     ports 388h-38Bh (trapped by VSBVXD).
   - drv/GENMIDI.C is generated by drv/mkgenmidi.py from Freedoom's GENMIDI
     bank (BSD license, see the file). DMX note numbers are one octave above
     MIDI; the bank's base note offsets compensate that.


   7. Limitations / todo

   - First version: tested only in QEMU, not on real hardware yet.
   - No recording (the VSBHDA sound hardware drivers are output only), no
     MPU-401 MIDI output.
   - One wave and one MIDI output device, one open at a time each.
   - The SB belongs to the VM that accessed its DSP last.
   - SB16 16-bit DMA in DOS boxes and real games: not tested yet.
   - OEMSETUP.INF: not tested yet.
   - ES1370 (QEMU's emulation): the sound hardware interrupt comes too
     seldom, the output is played with gaps (SC_E1370.C is marked untested
     in VSBHDA as well).
